# What carries over from `metastable-2`

Status: review, 2026-09. This document re-reads the previous checker effort (branch `metastable-2`, tip `87e0853aff`, and the provenance work already on `main`) against the constraints of the restart, and says what to reuse, what to rebuild, and what to drop. No code was run for it; every number quoted is from a design record or a witness module doc.

## The constraints this review applies

1. The checker only has to work on idiomatic Hydro dataflow, where state lives in `use::state`, `use::state_null`, folds and keyed singletons, and logic lives in operators. Raft and every protocol written as one `by_mut` closure are out of scope.
2. The judge is the witness corpus (`design_docs/2026-09_witness_corpus_spec.md`): `rpc_retry` and the files under `hydro_test/src/cluster/witnesses/`, with labels confirmed by an 800-round harness that applies a load trigger during rounds 100 to 160 and measures the tail.
3. The end product is a deterministic tool that decides whether a unit has schedule-dependent work amplification and says where in the code the hazard arises, without a declared goal and without instrumenting the program.
4. Provenance, counterfactual replay, and an adversarial scheduler are mental models that may or may not be needed.

Two facts about the corpus as written matter more than anything in the old branch, so they come first.

**Three of the four matched twin pairs have identical dataflow.** `rpc_retry` with `max_attempts = 3` and with `max_attempts = 1` differ by a captured constant. `bounded_queue_rejection` with `max_backlog = Some(100)` and with `None` differ by a captured constant (`None` becomes `usize::MAX` inside the placement closure; the reject path exists in both). The request-dated and fill-dated cache differ by which field a `map` closure reads (`f.issued_at` against `now`). Only the coalescing twin differs structurally, by one `filter_key_not_in(pending.keys()).first()` on the fetch path. No analysis that reads the IR without running it can label three of the four pairs, so the verdict must come from behaviour and static analysis can at most localize and prune.

**The corpus label is persistence, and the old branch measured gain.** The spec labels a witness amplifying when pending work keeps growing after the trigger is removed and a control recovers. The old sweep applied a perturbation for the whole run and reported gain and a transient/sustained split under that continuing perturbation. Those are different questions. The fill-dated cache herd has real gain (568 redundant fills) and is labelled benign because it recovers; the bounded queue re-sends 1.38 times the input and is benign for the same reason. Any technique carried over must be re-aimed at the tail after a bounded perturbation.

## 2. What to port or rebuild, for each surviving technique

**Hold schedules and the empty-tick option.** Port `hydro_lang/src/sim/hold_schedule.rs` and `edge_counts.rs` from `87e0853aff` together, since `HoldScheduleDriver` reads `edge_counts::current_hook` to learn which hook is asking. Both need the `SimHook` additions in `runtime.rs` (`edge_location`, `pending_release_len`, `buffered_len`, `pending_release_positions`) and the `run_hooks` changes in `compiled.rs` that record releases and honour `with_empty_ticks_allowed`; `git diff main metastable-2 -- hydro_lang/src/sim/runtime.rs hydro_lang/src/sim/compiled.rs hydro_lang/src/sim/builder.rs` is about 430 lines, of which the lineage id plumbing (`pending_release_records`, `pending_release_ids`, `format_item_serialize`) can be left out at first. Nothing in these files knows about goals or Raft. The one change worth making on the way in is edge identity: a hook's location is the `sliced!` invocation plus an index, so two batches in one slice share a line, and the design record already asked for an operator id in the IR metadata.

**Per-edge counts.** Same commit, same port. Keep it passive and host-side as it is. Add nothing yet.

**The sweep, re-aimed.** Port `sweep.rs` but change three things. First, the perturbation must be bounded: an `EdgePolicy` that applies `Hold(d)` or `Periodic` only between two decision indices and is `Prompt` outside them, so a cell reports the tail after the perturbation ends rather than the gain during it. Second, the verdict column must not need `Program::goals`: start with per-edge counts in the tail against prompt, and add the payload-shape column (the `Debug` rendering with digits stripped, already implemented in `counterfactual.rs`) as the program-knowledge-free answer to displacement. Third, the driver has to work with the corpus's harness shape, which sends one clock element and a round's data, then calls `quiesce()`. Under the forcing rule a held response is forced out inside its own round, which is why the old harnesses sent the whole clock up front and metered it; under `with_empty_ticks_allowed` a hold is measured in hook decisions inside the quiesce loop, and nobody has checked that this behaves. This is the first experiment in section 5, because if it fails the corpus harnesses need a second, metered-clock driver entry, and `rpc_retry.rs` on `metastable-2` (lines 674 to 2026, dropped from the port) shows what that looks like.

**Derived goals instead of declared ones.** `lineage.rs::per_goal` (the boundary log, 802 lines, 17957c8674) is worth porting only if the identity pass supplies its extractor. Otherwise the per-edge and per-shape counts do the same job for additive amplification and the boundary log is dead weight.

**The identity pass.** Port `identity.rs` and `CompiledSim::operators()` (both in 87e0853aff) together with the part of `lineage_pass.rs` that builds the operator table (`OperatorInfo`, the `negative` flag), which can be done without the record-id rewrite. Run it on the corpus before anything else in this group. Its two outputs are a candidate goal extractor per edge (the key type of the keyed operator the edge feeds) and a static list of loci where the program tests absence or deduplicates, which is the natural starting set for both the sweep's candidate edges and the localization report.

**Lineage pass and negative leaves, later.** `lineage_pass.rs`, `lineage_rt.rs`, and the `per_goal_by_ancestry` and `re_derivations` methods of `lineage.rs` are the tool that names the operator. Leave them on the old branch until the verdict pipeline reproduces the corpus labels, then port them for the localization step only and pay the 103 s per run there.

**Counterfactual forks, later.** `counterfactual.rs` depends on `sweep::Program` and `Run`; port it after the sweep is re-shaped, and only as the second localization tool.

**One extra witness to consider.** `hydro_std/src/ec_inference_demos/multi_paxos_live.rs` on `metastable-2` is a simulator-runnable Multi-Paxos with a timer input and a measured redo-queue amplification (accept traffic 3.5 times prompt, commands decreed up to 15 times under bursty acks). It is not idiomatic in the sense of constraint 1 if its kernel is a closure, so it belongs to the corpus author's judgement, not this review.

## 3. How the survivors would behave on the matched twins

This section reasons from mechanism; nothing was run.

**`rpc_retry` against `max_attempts = 1`.** Any schedule that delays responses past 40 ticks produces re-sends in one and none in the other, and the re-sends add records to the arrivals, processed and responses edges without displacing anything. Per-edge counts separate the pair under a continuing hold (5,000 against 2,400 was measured), and a windowed hold should still separate them if the re-sends during the window build a server queue that outlives it; whether it does at capacity 5 is exactly what experiment E2 below measures. The identity pass sees the same `unique()` and `filter_key_not_in` in both and says nothing about the label.

**`rpc_retry` against `bounded_queue_rejection` with `Some(100)`.** This is the pair the old move set gets wrong. Holding the responses edge at the client keeps the server's `backlog` state empty, so `max_backlog` never fires, the client times out in both programs, and both re-send; the two look identical under every release-timing move. The bound only matters when the server's own queue exceeds 100, which a hold cannot cause and a burst can: `Periodic { period: d }` on the arrivals edge releases `2d` requests into one server tick, the bounded server rejects the excess in the same tick, the client re-sends after 10 ticks and is served once, while the unbounded server queues everything and serves each request up to three times. The separating signal is the `processed` edge in the tail (bounded: each id once; unbounded: 667 of 1,000 served again) and whether the tail returns to prompt. So the bursty shape is not optional, and the verdict must be read from the tail. A static reading of either program finds a reject path in both.

**Cache with and without coalescing.** Structurally different, and behaviourally separable under a hold or burst on either the fetch edge or the fill edge: while a hot key is missing, the herd issues one fetch per lookup and the coalescing cache one per key, so the fetches edge count differs by the number of lookups per key per outage. Per-edge counts get this pair right under any move that makes a key missing for more than one tick.

**Request-dated against fill-dated cache.** Same dataflow, one closure differs, and the difference only shows when the origin's queueing delay exceeds the TTL of 20. A hold on the fills edge does not build an origin queue (the origin has already served them), so that move labels both benign. A burst on the fetches edge does: `2d` fetches land at once against a capacity of 4 per tick, the last is served `d/2` ticks later, and if that exceeds 20 the request-dated cache discards the fill as stale and re-fetches while the fill-dated cache stores it and stops. The witnesses' own measurement says the loop closes for request-dated (origin queue 2,462 to 3,258 in the tail) and not for fill-dated (peak 680, drained). The sweep has to try the fetches edge with a bursty move at `d` of roughly 40 or more, and the tail must be inspected after the burst window closes. This is the pair that most needs the windowed perturbation; under a continuing burst both show gain.

**Gossip.** No retry, timeout or acknowledgement exists; every move changes convergence time and never the number of sends per pump, so per-edge counts in the tail equal prompt under every schedule. The old sweep's corpus controls behaved this way. One caution: the deliveries land in a `TopLevelFoldHook`, which `Hold` never supported and which under the prompt driver releases one element per decision; the port must either implement `Periodic` for it or record that the edge was not moved.

**The in-scope hard case is W5, the election stampede.** Its goal (a leader) is abstract, its messages carry a term that changes per attempt, and elections displace heartbeats. Per-edge totals may fall while it storms, exactly as on Raft, and the identity pass will return the term as the receiver's key, which is a stamp. The per-shape column (vote requests against heartbeats on one edge) is the only program-knowledge-free signal the old work found for this shape, and it was right on Raft by payload shape. Whether W5 collapses under load, and whether the shape column ranks it, are open until the witness lands.

## 4. What the localization requirement implies

The requirement is to say where in the code the hazard arises. The techniques differ in what they can name.

The sweep names an edge: the `use::batch` whose delayed or bursty release produced the tail excess, and the edges where the excess appeared. That is where the delay must happen, which for `rpc_retry` is the responses or arrivals hook and for the cache is the fetches hook. It is a location the programmer can act on (bound that buffer, back off that retry), and it needs no program knowledge, but it names the input to the loop rather than the operator that closes it.

The negative-leaf rule names the operator: the absence test whose output was re-derived while a delivery was held. On `rpc_retry` that is the `filter_key_not_in(responded_ids)` in the client slice, which is the retry decision itself. On idiomatic code this is exact and is the most precise answer available, at the cost of the lineage pass and its runtime.

The identity pass names candidates statically: every `unique`, anti-join, keyed fold and keyed state in the unit, with the key type. It cannot separate any twin, but it prunes the sweep (only edges feeding an absence test can manufacture work) and gives the report a place to point before any run.

Counterfactual forks name a delivery and list the records it caused, per edge and per shape. That is a good explanation of one cell and a poor substitute for the operator, because a storm has no single owner and on a totally ordered hook the fork releases the whole buffer.

Per-edge counts name edges only when compared across schedules; provenance labels, feedback campaigns and PerfFuzz give program-level verdicts and no location.

Two plumbing items follow. Edge identity must become an operator id in IR metadata rather than the `sliced!` line plus an index, or the report will name a slice rather than a line. And the checker must find its edges from a compiled program without a harness declaring them, which `CompiledSim::operators()` already does for operators and the prompt run does for hook edges.

## 5. Recommended order of experiments

Each experiment ends in a command run against the corpus, and each has a pass criterion stated in the corpus's labels. Cheapest first.

**E1. The round-based harness can hold.** Port `edge_counts`, `hold_schedule` and `with_empty_ticks_allowed`. Run `rpc_retry`'s own 800-round harness, no load trigger, under `HoldScheduleDriver` holding the client's responses hook at `d = 41` for the whole run. Pass: total sends exceed 2,200 and the `max_attempts = 1` twin's sends equal 1,600. Fail: `quiesce()` never returns, or the hold is flushed within its round; then the corpus harnesses need a metered-clock entry point and the old `amplification_tests` harness is the model.

**E2. Schedule alone reproduces the label.** Same harness, the hold applied only during rounds 100 to 160, then prompt. Pass: `rpc_retry` shows zero tail completions or a growing backlog, and both controls (`max_attempts = 1`, no hold) recover. Fail: `rpc_retry` recovers, which means a hold on responses does not build a server queue at capacity 5 and the checker's move set needs release-size moves (bursty arrivals) before anything else. This experiment decides whether the checker can work without a load trigger at all.

**E3. The bursty move separates the queue twins.** `Periodic { period: d }` on the arrivals hook during rounds 100 to 160, `d` on a grid from 8 to 64, on `bounded_queue_rejection` with `Some(100)` and `None`. Pass: at some `d` the unbounded program's tail `processed` count exceeds prompt and the bounded program's equals it. Fail at every `d`: the twin cannot be separated by scheduling, and the corpus label for it rests on load only, which should be recorded in the spec.

**E4. The sweep without a goal, on the corpus.** Port `sweep.rs` with the windowed policy and the per-edge tail column, no `goals`. Run it on the seven labelled configurations. Pass: four amplifying (`rpc_retry`, unbounded queue, request-dated herd, and whichever of W3, W5, W7 has landed as amplifying) show a tail excess on some edge and the benign ones (`max_attempts = 1`, bounded queue, both benign caches, gossip) show none on every edge. Any miss names the missing move or the missing column.

**E5. The identity pass on the corpus.** Port `identity.rs` and the operator table, run without a simulation. Pass: `rpc_retry` and the bounded queue yield the request id, the cache yields the key for `entries` and `pending` and the lookup id for `waiting`, gossip yields the set element. Record what W5 yields; the prediction is the term, which is a stamp.

**E6. The shape column on W5.** Once W5 has a measured label, run E4's sweep with the payload-shape column added. Pass: the storm cell ranks above prompt by shape even if its per-edge total is lower. Fail: W5 joins Raft as a case the program-knowledge-free verdict cannot rank, and the checker's report must say so.

**E7. Localization on the found cells.** For each amplifying cell from E4, run the lineage pass with negative leaves and, separately, forks at the held decisions. Pass: `rpc_retry` names the `filter_key_not_in` on responses and the cache names the miss path's fetch construction; the two tools agree on the edge. This is the last experiment because it is the most expensive and because its output is only useful once the verdict is trusted.
